# Grid Wallpaper

- This repository owns the offline Canvas runtime and Windows installation package. It must run without adjacent checkouts, personal tooling, a separately configured server or Node.js on the receiving laptop.
- `wallpaper/` owns the browser runtime, Lively metadata and preview assets. Keep the release ZIP and installed Lively folder flat; source organization must not change native resource names or require development tools on the receiving laptop.
- `wallpaper/grid-config.js` owns defaults, numeric limits, presets and the settings link. Its sibling `LivelyProperties.json` and `windows-integration.json` are generated metadata: run `npm run generate` and validate parity instead of editing them directly.
- `wallpaper/grid-wallpaper.js` owns simulation, rendering, validated browser persistence, Lively callbacks and live telemetry transport. Its sibling `grid-settings.js` owns the settings UI and native bridge; `grid-wallpaper.css` owns their appearance. Preserve the private scopes and renderer-before-telemetry / native-bridge-before-UI initialization order within those modules.
- Preserve that custom panel on the desktop. `windows/settings-window.cs` hosts the same HTML above desktop shortcuts, anchors its top-right corner to the settings button's center within the display work area, and clips the native window to the CSS corner radius. Do not replace the panel with Lively's generated editor.
- Opening and closing must be responsive. The native launcher owns desktop mouse capture and toggles the warmed panel directly. Its appearance comes from the existing CSS and SVG through `grid-settings.js`; browser preview retains its inline button. Do not depend on wallpaper-forwarded input for desktop dragging or launch a URI-handler process for each normal click.
- Keep the open panel attached while dragging its launcher, including edge snapping. Outside activation dismisses the panel; the launcher, panel controls and owned popups remain one interaction group. Preserve decorative control motion with immediate input and reduced-motion support.
- Live dome readouts come from actual rendered state and telemetry transport in `grid-wallpaper.js`, through the helper's `windows/dome-telemetry.cs`. Keep this authenticated loopback stream read-only and bounded, request frames only for visible automatic-size readouts, and never persist live samples or simulate them independently in the panel. `grid-config.js` owns pulse bounds; generated integration metadata carries them to the helper.
- Reuse the warmed WebView2 control and suspend it while hidden after saving. Dispose the browser and launcher when Lively exits; a lightweight dormant supervisor restores them when Lively returns. The installer owns its reversible native per-user warm-start entry. `grid-settings.js` bridges validated changes to Lively; acknowledge saves only after native persistence is confirmed.
- `windows/wallpaper-lifecycle.cs` owns current Windows display matching, owned-player detection and bounded startup recovery. Ignore disconnected saved display entries when selecting the current primary. Recover only an unchanged, unambiguous single-display Grid selection during Lively startup through native `setwp`; never restart Lively, rearm after a user closes/selects wallpaper, or treat a visible launcher as playback evidence.
- `scripts/build-settings.ps1` owns the pinned official WebView2 SDK, the pinned official Roslyn compiler toolset and the native build. Both dependencies are build-only, pinned by exact version and SHA512 through one shared resolver, and cached under ignored `dist/`; the helper compiles deterministically so a recorded release digest is verifiable. Package its required redistribution license. `windows-host.json` contains installed-machine paths and `windows-telemetry.js` contains a protected session capability; both must remain local and excluded from packages and Git.
- `scripts/thumbnail.cjs` renders the checked-in library thumbnail and animated preview from the runtime. Regenerate with `npm run thumbnail` when their appearance changes; native metadata and the package allowlist must include both.
- Preserve the single animation scheduler, frozen redraw, bounded resume timing and native host pause behavior. Runtime/browser checks and actual Windows desktop acceptance prove different things.
- `.gitattributes` owns line endings and `scripts/package.ps1` owns archive entry order and timestamps, because package bytes are this repository's release evidence. Do not rely on a local `core.autocrlf` setting, and do not reintroduce `Compress-Archive`. `.githooks/pre-push` with `.gitleaks.toml` owns the local pre-push secret scan; it requires `git config core.hooksPath .githooks` in each clone.
- Use `OPERATIONS.md` for validation, package, install and rollback procedures. Native GitHub issues own remaining work; delivery #1 is accepted and closed, #30 owns the one unperformed hardware scenario, and #6 records the accepted privacy/publication review.
- Development validation stays local. The Owner authorizes GitHub Actions only for this repository's final production/release work; `OPERATIONS.md#github-release-security` owns the bounded execution requirements. Do not infer authorization for development runs or other repositories. Automatic Copilot review was confirmed disabled by the Owner; do not repeatedly request that confirmation without new evidence of a change.
- Publish each coherent, locally validated checkpoint and update its affected GitHub issues and PR before starting the next implementation increment. Keep remaining desktop acceptance explicit in the tracker; it is not a reason to accumulate validated changes only locally. At interruption or handoff, reconcile the working tree, remote branch and issue evidence.
- Follow the native branch/tag protections and the GitHub release-security procedure in `OPERATIONS.md`. Preserve public account/no-reply commit attribution when merging. Validate locally, build through the selected release procedure, attach and verify assets on a draft, then publish under native release immutability.
- This repository is public following the Owner-approved review in #6. Keep source, issue/PR text, logs and release artifacts safe for public access. Do not copy nonpublic identities, installed session files or sensitive findings into them; report vulnerabilities through the private channel in `.github/SECURITY.md`. Recheck changed publication surfaces before each release.
- Keep every public surface about this project only. Commits, guidance, issues, pull requests, release notes and packaged files must not name the Owner's other repositories, products or clients, describe another project's internal documents or structure, or report what else is running on the development machine. Describe an external owner by its role rather than its name, and keep host measurements general enough that they say nothing about unrelated work. The one deliberate exception is the legacy `Ventryn LLC` author string, which the installer must still recognize to migrate an older installation and which the licensing decisions in #17 and #18 already made public.
- Broader operating policy is owned outside this repository and is not named here. Keep this repository self-contained and record only its runtime and release-specific requirements.
